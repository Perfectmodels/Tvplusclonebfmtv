# Parcours d'achat du direct
/direct?offre=<slug> → inscription/connexion → confirmation e-mail (PKCE dans le même navigateur, ou modèle token_hash à configurer) → offre conservée → récapitulatif et consentement → POST /api/premium/payment → portail SingPay → /direct/paiement?reference=<uuid> → interrogation serveur de SingPay → droit au direct après résultat vérifié. Replays gratuits.
Le compte public est un reader actif sans permission éditoriale. Confirmation e-mail obligatoire côté serveur. Configurer Site URL et URLs de redirection /auth/callback dans Supabase Auth, SMTP et confirmation d'e-mail ; ne pas activer l'auto-confirmation. Le compte ne dépend pas de l'ancien service MySQL.
Paiements : clé Supabase privée uniquement serveur, offres réelles saisies dans /admin-v2/premium, configuration SingPay et broker vidéo signés validés. Aucun encaissement ouvert. Les tests SQL transactionnels sont annulés, aucun appel au fournisseur effectué. Les remboursements et la migration des transactions antérieures restent des prérequis avant mise en service.
Commit isolé sans mise à jour du ref GitHub pour éviter les builds Vercel automatiques. Compilation et tests intégration nécessaires avant toute publication.
