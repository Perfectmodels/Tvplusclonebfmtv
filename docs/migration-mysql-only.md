# Migration vers MySQL LWS — état de travail
Branche feat/mysql-only, basée sur integration/lws-api-v3. Conserver les branches de référence, aucune fusion ni modification des bases en production.
Source unique visée : Next.js -> API HTTPS PHP LWS -> tvplus_v3. Les lectures publiques, la session et l'authentification utilisent LWS. Vercel Blob exclusivement pour les nouveaux médias. Les anciens clients historiques sont bloqués localement; des références TypeScript et routes héritées restent à éliminer, notamment la régie destinations/secret de diffusion et anciens modules admin. Ne pas retirer les dépendances avant inventaire et compilation de ces routes.
Migration additionnelle deploy/lws/editorial/upgrade-mysql-only.sql à valider avec le schéma réel. Ne pas exécuter les migrations PostgreSQL préparées dans l'autre branche. Installer les fichiers PHP modifiés dans l'environnement de test, sans modifier le site historique.
Variables serveur : LWS_EDITORIAL_API_URL, LWS_EDITORIAL_SERVICE_KEY, AUTH_SESSION_SECRET (32 caractères minimum), BLOB_READ_WRITE_TOKEN, CRON_SECRET. Pas de clés historiques exposées au navigateur. Le lecteur Premium exige LIVE_TOKEN_BROKER_URL, LIVE_TOKEN_BROKER_SECRET, LIVE_EMBED_HOSTS. Aucun paiement activé.
La migration des comptes historiques nécessite vérifier les hachages et droits, et réinitialiser les mots de passe incompatibles. Les anciens médias hébergés ailleurs doivent être copiés vers Blob et les URL mises à jour après contrôle. Ne pas supprimer les originaux avant vérification.
Recette : PHP lint, npm ci, npm run typecheck, navigation, build, tests authentification, droits, lectures et modifications d'articles, pagination, replays, publicités, programme, catalogue, Restream. Vérifier aucune requête vers l'ancien fournisseur avant retrait définitif des packages. Le rétablissement du flux Premium dépend du broker sécurisé.
