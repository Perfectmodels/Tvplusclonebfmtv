# Correctif Direct Premium
## Base MySQL V3
Appliquer upgrade-premium-settings.sql sur la V3 après sauvegarde. Le script est additif, ne change aucun prix, n'active aucun paiement.
## Déploiement PHP impératif
Dans cPanel > Domains identifier la racine documentaire exacte de api-v3.tvplusafrique.com. Sauvegarder le dossier existant, puis copier depuis deploy/lws/editorial/ du commit de release : index.php, newsroom.php, admin.php, programming.php, extras.php, payments.php, studio.php, whatsapp.php (et uniquement les fichiers PHP opérationnels, pas les scripts d'installation/migration). Ne pas remplacer tvplus-v3-private.php, qui reste hors racine publique. Vérifier avec php -l avant installation. Ne pas publier un secret de service.
L'API GET ?resource=premium_plans doit renvoyer plans et settings, sans identifiant privé. GET ?resource=health doit fonctionner. Les écritures utilisent newsroom avec la clé serveur existante. Si auth.me ou payments.admin renvoie 403, vérifier d'abord la concordance LWS_EDITORIAL_SERVICE_KEY et config service_key, puis le rôle et permissions en base. Ne pas désactiver l'authentification.
## Gestion et parcours
/admin-v2/premium : offres, prix, durée, activation de visibilité ; configuration non secrète du paiement. Les encaissements sont ouverts uniquement via la configuration explicite de l'administrateur, après validation des prérequis. SINGPAY_HARD_DISABLE=true permet un arrêt d'urgence ; les identifiants restent des variables serveur. Le lecteur sécurisé doit être réellement configuré et vérifié. Le mode sandbox utilise uniquement des identifiants de test.
Le public consulte /direct sans connexion, choisit une offre, voit le récapitulatif, crée un compte ou se connecte puis revient sur la formule sélectionnée. Le paiement externe reste inaccessible tant que l'administrateur ne l'a pas ouvert et que les prérequis ne sont pas réunis. Les tarifs sont uniquement lus depuis MySQL. La route /api/live-stream reste privée ; un 401 sans abonnement est normal.
